# 生产计划排产优化设计

> 基于 v4 版本的改进，聚焦三个优化点

## 1. 新增尺码列

### 位置
产品列（E 列）后插入 F 列「尺码」，原有列全部右移一位。

### 提取规则
从产品名中按优先级匹配：

| 优先级 | 模式 | 匹配内容 |
|--------|------|---------|
| 1 | `XL码` | 优先匹配，避免被 L码 误匹配 |
| 2 | `L码` | 注意：`XL码` 已在步骤1处理 |
| 3 | `M码` | |
| 4 | `S码` | |

### 特殊规则
- 带括号注释如 `L码(产品标注XL码)` → 取第一个匹配，即 L
- 产品名中出现多次尺码 → 取第一个
- 未匹配到 → 留空，手动补填

## 2. 换码逻辑改为按尺码

### 变更
- **原来**：比对 G 列完整规格字符串（如 `10*8`），不同规格 = 换码
- **现在**：比对 F 列尺码（S/M/L/XL），不同尺码 = 换码

### 场景

| 上一条产品 | 本条产品 | 换码？ |
|-----------|---------|:----:|
| L码 10*8 | L码 12*4 | 否（同尺码） |
| L码 10*8 | S码 10*8 | 是（换尺码） |
| M码 10*12 | M码 10*8 | 否 |

### 影响范围
- Excel Row 3 换码损失公式：`COUNTIFS` → 引用尺码列代替规格列
- VBA `StartScheduling`：spec 比对 → 尺码比对

## 3. 排产算法优化

### 原有问题
当天剩余产能不足以排一整箱时，VBA 仍会分配零头（如 1 箱），现实中不可能。

### 修正
- `maxCases = availableCapacity \ piecesPerCase`
- 若 `maxCases = 0`：跳过当天，订单推至下一天
- 允许当天产能有小幅剩余（不足一箱的部分直接留空）

### 算法不变的部分
- 按订单行序从上到下
- 逐天填满再进入下一天
- 换码损失按尺码自动扣减
